# 프로젝트 요약 (신용평가모형 자동 점검 시스템)

## 1. 주제
- 신용평가모형 자동 점검 시스템
- 대출 심사용 신용평가모형 1개를 3개월마다 자동 점검
- 예측 상각률과 실제 상각률의 차이 확대 시 모형 수정안을 비교해 담당자에게 보고
- 적용 여부는 담당자 결정

## 2. 목표와 필요성
### 필요성
- 신용평가모형은 개발 시점 자료로 학습. 시간 경과에 따라 고객 구성과 경기 변화로 예측이 실제와 어긋남
- 본 자료 기준 2016년 대출의 실제 상각률 13.8%, 모형 예측 10.2%
- 상각 결과는 대출 후 2년 반 경과 후 확정, 문제 발견 지연
- '그대로 사용, 예측치 조정, 재학습' 판단은 담당자 반복 업무. 매번 재학습 시 비용과 불안정성 증가

### 목표
- 예측 오차의 조기 발견
- 수정안 효과를 당시 자료로 검증한 뒤 권고
- 변경이 불필요한 경우 현행 유지 판단까지 자동화

## 3. 주제 선정 배경 (기획 문서 기준)
- 이전 프로젝트(연체 채권 손실 예측)에서 같은 Lending Club 자료의 연도별 상각률 상승 확인, 2013년 8.3%, 2015년 10.7%, 2016년 11.5%
- 리스크 직무의 모형 운영 업무(정기 점검, 재보정, 재학습 판단)를 반복 업무 자동화 대상으로 설정
- BCG X 인턴 경험(자료 구축, 모델 개발, 실사용 검증)을 금융 모형의 지속 사용 판단 문제에 적용

## 4. 기술 스택
| 구분 | 사용 기술 |
|---|---|
| 자료 처리 | Python 3.12, pandas, NumPy, DuckDB, Parquet(PyArrow) |
| 모형 | LightGBM(운영 모형, 재학습), 로지스틱 회귀(기준 모형), scikit-learn(확률 보정, isotonic), statsmodels, SciPy |
| 자동화 | APScheduler(정기 실행), 실행 이력, 버전 관리(JSON), pytest(테스트 16건) |
| 보고 | 규칙 기반 보고서와 수치 자동 대조(항목별), Claude API(Opus 5.5) 보고서 초안과 자동 검사 |
| 화면, 배포 | HTML, JavaScript(SVG 그림), GitHub Pages, QR 코드 |
| 발표 자료 | python-pptx, PowerPoint 변환, Matplotlib |

## 5. 파이프라인
1. **자료 정리** Lending Club 대출 226만 건. 대출 실행 시점 변수 사용, 사후 정보 제거
2. **상각 정의** 대출 후 2년 내 상환 중단 후 손실 처리. 결과 확정 시점(대출 후 30개월) 계산
3. **운영 모형 학습** 2010~2013년 상반기 대출 14만 건 (첫 판단 시점에 결과가 확정된 자료 전체), 신용조회 확장 변수, 최근 대출 가중. 2013년 하반기~2016년 대출로 시간외 검증
4. 분기별 자동 실행 (2015년 4분기~2018년 4분기, 13회). 각 시점까지의 정보 사용
   - **점검** 신규 대출 구성, 대출 후 1년 상각 결과(중간 신호), 2년 상각 결과
   - **판정** 정상, 주의, 조치 필요, 판단 보류
   - **원인 유형 진단** 자료 오류, 고객 구성 변화, 상각률 수준 오차, 순위 구분 저하
   - 조치 필요 또는 1년 중간 실적 기준 초과 시 수정안 12종(예측 상각률 조정 8종, 재학습 4종) 비교
   - 확률 수준 오차는 1년 중간 실적 4개 분기 추세로 보유 대출 수준을 추정해 10% 이상 차이 시 조정 권고
   - 보고서 생성, 숫자 자동 대조 (불일치 시 발행 보류)
5. **사후 평가** 권고안을 당시 보유 대출에 적용해 이후 실제 결과와 비교
6. **운영 방식 비교** 고정 모형, 3개월마다 재학습, 단순 기준 재학습, 본 시스템
7. 결과 화면 생성과 공개 (GitHub Pages)

## 6. 성능 (운영 모형 v2, 규칙 r5)
| 항목 | 결과 |
|---|---|
| 예측모형 변별력(AUC) | 0.701, 기존 0.681 (공개 연구 동일 조건 0.65~0.71) |
| 상각률 이상 경고 | 6개월 전 사전 예측 (대출 후 1년 중간 실적 활용, 기존 2년 실적. 2016~2017년 단일 사례) |
| 수정안 효과 (권고 10개 시점, 당시 보유 대출) | 예측 오차(상대) 평균 31%에서 6%로. 2018년 1분기 33.5%에서 0.2%로 |
| 운영 방식 비교 (3년 평균 오차, 갱신 승인 가정) | 고정 모형 28.5%, 3개월마다 재학습 18.8% (갱신 13회), 단순 기준 재학습 18.2% (6회), 본 시스템 9.5% (2회) |
| 변별력과 log loss (운영 방식 비교) | 본 시스템 AUC 0.703, log loss 0.366. 3개월마다 재학습 0.701, 0.368 |
| 판정 기준 모의 검증 (각 300회) | 오차 없는 상황의 조치 필요 오경보 0% (주의 3.7%), 오차 20% 이상 발견율 100% |
| 안정성 | 오류 주입 시험 6건 통과, 상각 확정 시점 가정 변경 시 13개 분기 중 10개 판정 동일 |

- **예측 오차** |실제 상각률 ÷ 예측 상각률 - 1| (상대 오차)
- **평가 대출 수 가중 평균 오차** 고정 모형 27.0%, 3개월마다 재학습 22.5%, 본 시스템 11.9%
- 수정안 효과와 운영 방식 비교는 별도 실험. 운영 모형 v2 설정과 규칙 r5는 같은 기간 결과를 보고 정한 탐색 단계 결과 ([10_성능개선_r5](10_성능개선_r5.md))
