## 2. 갱신 방식 개선
### 원인 분석
- 기존 수정안 검증은 2년 반 전 대출(24개월 결과 확정분)로 수행
- 2015~2016년에는 오래된 대출의 상각률이 예측보다 낮고 최근 대출은 예측보다 높아 방향이 반대. 오래된 대출 검증이 최근 흐름을 반영한 수정안을 탈락시켜 갱신 지연
- 대출 후 1년 중간 실적은 판단 시점 기준 1년 이상 최신 정보

### 빠른 시험 (`m18`, `m19`, 재학습 제외)
| 방식 | 보유 대출 평균 오차 | 갱신 횟수 |
|---|---|---|
| 갱신 없음 | 28.5% | 0 |
| 24개월 결과 검증 (r4 방식) | 11.9% | 7 |
| 1년 중간 실적 추세, 매 분기 적용 | 8.5% | 13 |
| **1년 중간 실적 추세, 수준 차이 10% 이상 시 적용 (r5)** | **9.1%** | **4** |

- 운영 모형 v2 기준. 보유 대출 결과는 평가에 사용, 방식 선택은 이 결과를 보고 결정 (탐색 단계)

### r5 규칙
- **수정안 추가** 조기 결과 추세 반영 재보정. 1년 중간 실적 최근 4개 분기의 분기별 수준 차이를 구하고 선형 추세를 보유 대출 중심 시점까지 연장
- **선택** 확률 수준 오차 유형에서 추정 수준 차이가 logit 0.10(약 10%) 이상이면 해당 재보정 권고, 미만이면 갱신 보류. 순위 악화 유형은 기존 재학습 우선 규칙 유지
- **실험 실행 조건** 조치 검토, 또는 주의 중 1년 중간 실적 기준 초과
- 24개월 결과 모의 배포 검증표는 비교 자료로 유지

## 4. 운영 방식 비교 계산 오류 수정
- `m11_policies.py`의 `set_active()`가 모형 갱신 뒤 조기 기대 함수(24개월 확률에서 12개월 확률로의 변환)를 개발 구간에서 다시 적합
- 수준 재보정 뒤 다시 적합하면 개발 구간 수준으로 되돌아가 보정 효과가 사라지고, 같은 이동이 반복 적용됨
- 수정 후에는 재학습 때 다시 적합하고 수준 재보정 때 유지
- r4 운영 방식 비교 결과(본 시스템 17.3%)도 같은 계산 방식이었으므로 r4 수치는 참고용으로만 보존 (`results/*_r4.*`)

## 5. 한계
- r5 규칙과 모형 v2 설정 일부는 같은 재현 기간 결과를 보고 결정한 탐색 단계 결과. 독립 기간 검증 미실시 (실적 확정 자료가 2016년 3분기 실행분까지)
- 조기 결과 추세 연장은 추세가 급변하는 시기에 과대 또는 과소 조정 가능. 추세 연장 폭은 관측 범위 ±0.3 logit으로 제한
- 수준 재보정은 순위(AUC)를 바꾸지 않음. 순위 악화는 재학습 경로로 처리
